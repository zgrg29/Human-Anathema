# 《非人与尘世》设定与系统设计基准

> 具体系统规则以主题文档为准： [角色属性与战斗规则](character-combat.md)、[成长、注射与阵营系统](progression-injection-alignment.md)、[交涉、队友与结局](social-and-endings.md)。本文件用于记录跨系统设计原则和仍待决定的问题。

> 用途：在实现游戏核心代码前，集中记录目前企划的设定边界、设计意图和未决问题，避免把临时假设固化进代码。
>
> 状态说明：
> - **已确定**：README 明确提出的方向或规则；仍可能在后续版本中经团队讨论修订。
> - **设计原则**：由现有目标归纳出的约束，用于指导后续设计，不等于新增世界观事实。
> - **待决定**：当前资料没有答案；实现前应决定，或明确标注为原型暂定值。

## 1. 项目目标与当前优先级

### 已确定

- 类型为无跑图、菜单驱动的回合制战术 RPG，主要循环由战斗阶段和整备阶段构成。
- 体验重点是策略、资源管理、博弈，以及凡人面对强敌时的脆弱感和抉择代价。
- 核心角色可以全程不注射，以纯人类状态通关；也可以逐步异变，进入不同结局路线。
- 核心逻辑计划先以纯文本 Headless API 实现，与未来表现层分离，并支持自动化平衡验证及 RL 兼容。
- 当前设计优先级是可理解、可推演、有构筑空间的战斗与战斗外配装；主线故事暂缓，不作为当前设计的前置条件。
- 不考虑 PVP 平衡；当前只以单人对抗敌人的体验为目标。将来若做 PVP，再单独评估规则适配。

### 设计原则

- 规则表达应服务于“脆弱的人类如何靠准备、判断和代价取胜”，而不是靠刷取经验不断提高数值。
- 注射既是力量来源，也是持续改变角色状态和关系的选择；不应只是无代价的升级按钮。
- 战斗胜利应更多来自针对敌人的情报、行动选择、资源使用与配置协同，而不是单纯高于敌人的等级或面板数值。
- 成长主要来自横向选择：装备、消耗品、样本能力、技能组合和队伍配置。奖励让玩家获得更多解法，不应普遍让旧解法失去意义。
- 菜单化不代表缺少叙事。设施、交谈、战前准备和战斗反馈都应承担世界观表达。
- Headless 核心应以明确状态、输入和结果描述行为；剧情文本和界面不应成为规则判定的唯一来源。

### 暂缓

- 故事前提、灾变起源、主角背景、章节剧情和最终 Boss 设定目前不作为战斗设计的前置条件，待核心战斗方向稳定后再设计。
- 目标平台、单周目时长、叙事呈现、内容规模、存档继承和周目结构暂不决定。

## 2. 世界与故事（暂缓）

当前暂不展开故事设定。为支撑战斗原型，只保留下列最低限度的抽象前提：

- 世界中存在可被击败并提供注射样本的敌人，也存在人类与怪物队友、黑市、炼金工坊、医疗所等社会设施。
- 玩家面对身体异变及其后果，故事基调偏向克苏鲁式的身体恐怖与痛苦抉择。
- 最终存在一名需要击败的 Boss；其败北时触发结局判定。

具体起源、地点、人物动机和故事冲突全部暂缓，不应为了战斗原型先行编造。

## 3. 异变、样本与侵蚀

### 已确定

- 主角开局为纯人类；可在战斗外或战斗回合中注射样本。
- 样本可由击败敌人获得。注射会立即恢复状态并提供强力 Buff，同时改变阵营坐标并累积侵蚀度（Corruption）。
- 敌人掉落的体液/样本是战后奖励资源，像其他掉落物一样进入玩家库存；它既可用于注射，也可参与后续交易、研究或构筑（后几种用途待定）。
- 注射有概率使角色随机习得相关技能；使用特定敌人的专属样本时，该敌人生前技能的抽取权重更高。
- 通过注射习得但未满足阵营门槛的高阶魔法处于“排异锁定”状态。
- 纯人类角色没有 MP，不能施放魔法，也不会触发注射带来的技能习得机制。
- 结局按侵蚀度和阵营坐标区分纯人类、未完全进化及四种完全异变结局。

### 设计原则

- “注射”至少需要分别记录即时战斗效果、长期角色变化和叙事/关系后果，避免一个数值代替全部代价。
- 特定样本与敌人身份、能力之间应有可追溯关系，便于玩家理解技能来源。
- 刷取样本的主要价值应是解锁选择、补充消耗资源或尝试构筑，而不是无限累积面板属性。
- 排异锁定需要明确反馈原因和解锁条件；不能让玩家误以为技能失效是随机故障。
- 纯人类路线需要有可行的战术工具和完整结局支持；“困难”不应等同于缺少可用玩法。

### 待决定

- 侵蚀度的具体范围、每次注射增量、是否有上限，以及“100%”如何达到。
- 侵蚀是否会随时间、休息、治疗或剧情选择下降；“零注射”是否严格等于侵蚀度为零。
- 注射是否可被拒绝、取消或中断；战斗中注射消耗多少 AP，能否被打断。
- 一次注射的恢复量、Buff 时长、叠加/覆盖规则、样本消耗量和重复注射后果。
- 样本如何分类（来源、属性、稀有度、专属技能、保存期限等），不同敌人的掉落池、掉落数量与保底规则。
- 是否允许重复刷同一敌人；若允许，如何限制单一掉落循环对构筑的支配性。
- 注射引发的身体变化如何呈现；是否存在阶段、外观变化、身体部位异变或不可逆变化。
- 注射是否影响主角的对话、行动选项、NPC 态度或结局之外的剧情门槛。
- 技能抽取概率、技能池、重复技能处理方式，以及锁定技能何时解锁。
- 怪物队友“可由样本强化”具体指什么；强化是否也带来侵蚀或其他代价。

## 4. 阵营坐标：两条互斥倾向轴

### 已确定的表达方式

用两个有正负方向的数值表示角色当前倾向。每条轴上，角色偏向一端就会远离另一端；同一条轴不同时拥有两端的分数：

- `law_chaos`：正值偏 **Law**，负值偏 **Chaos**。
- `justice_evil`：正值偏 **Justice**，负值偏 **Evil**。
- 两轴相互独立；坐标描述倾向，不直接等价于玩家善恶评价。
- 两个值各自在 -100 到 100 范围内。0 表示该轴上没有明显偏向；例如 `law_chaos = +70` 意味着偏 Law，不意味着同时拥有 Chaos 点数。

这将 README 的“秩序/混沌、正义/邪恶”明确为两个有方向的标量，而不是四个可独立累加的阵营值。代码与文档应统一使用 `law_chaos` 和 `justice_evil`，避免把端点误当独立资源。

### 设计原则

- 每条轴都应有自己的行为含义和玩法用途。Law/Chaos 衡量对规则、结构和不可预测变化的倾向；Justice/Evil 衡量对他人福祉、伤害与自利的倾向。以上是工作定义，具体行为映射需在内容设计时列例确认。
- 选择改变坐标时，应让玩家知道变化来自什么行为；必要时可在行动结果中说明变化量或倾向。
- 坐标可影响技能门槛、招募和 NPC 反应，但不应在没有提示的情况下随机改变关键角色的可用性。
- 固定阵营的队友拥有稳定立场；注射样本不能任意重写其核心价值观。

### 待决定

- 两轴各自的明确语义：秩序/混沌衡量什么？正义/邪恶衡量什么？
- 哪些玩家行为会改变哪条轴、变化幅度如何，以及变化是否有阈值/递减。
- 是否显示精确数值、区间标签、描述性反馈，或只在特定界面展示。
- 坐标相似度的距离公式：建议原型阶段采用归一化后的两轴距离，之后通过招募样例验证是否直观。
- 阵营是否能随行为双向变化；达到边界后是否钳制在 -100/100。
- 技能阵营门槛如何表达（单轴、双轴区域、阈值组合），边界值是否包含。

## 5. 玩家成长与构筑哲学

### 已确定

- 纯人类主角 HP 很低，大约只能承受 1–2 次攻击；不能通过常规升级提高 HP。
- 纯人类 MP 为 0，不能施法。
- 纯人类通过战斗中使用特定武器提升相应武器熟练度。熟练度不是角色等级，可提高武器伤害并减少 AP 消耗；具体成长幅度、上限和减耗规则待定。基础物攻不随通用等级提升。
- 非人/注射者可以通过注射获得恢复、Buff 和技能。
- 防具提供的 Shield 先吸收伤害；Shield 足够时本体无损，不足时溢出伤害施加给本体。当前原型在网咖付费休息时恢复 Shield；破裂规则仍待定。
- 不采用传统角色等级/经验升级作为主要成长路径；刷怪不能只为永久抬高攻击、防御或生命上限。
- 玩家追求的“变强”主要体现为调整装备、战术道具、样本带来的能力和招式配置，从而应对不同敌人或形成个人打法。

### 设计原则

- 战斗的主要决策应来自 AP、行动选择、防具/护甲、武器熟练、道具、交涉和注射时机之间的取舍。
- 由于主角容错很低，敌方攻击意图、可用防御手段和护甲状态必须清楚呈现。
- 纯人类不能施法的限制必须由装备、消耗品、队友协作和战术交互补足，而不是靠隐藏例外绕过。
- 成长优先提供“不同工具”而不是“同一工具更大的数字”。如果奖励直接提高基础数值，应有清楚的成本、上限或机会成本。

### 构筑维度（设计目标）

- **装备**：改变基础攻击方式、射程/目标范围（若适用）、AP效率、防御缓冲或弱点覆盖；装备槽和负重应造成真实取舍。
- **战术道具**：提供有限次数的控制、破甲、恢复、状态解除、侦察或临时增益；补足纯人类的应变能力。
- **技能**：每个技能要有明确用途、成本、目标、时效和反制窗口；避免只是同成本下严格更高伤害的“必选升级版”。
- **样本/注射**：提供强力且有代价的主动能力或状态改变；库存与注射风险构成战略取舍。
- **熟练度**：体现对特定武器的使用经验，但数值加成应渐进、有上限且不取代装备和战术选择；AP 减耗需要明确封顶，不能让强力动作变成零成本循环。
- **队伍配置**：队友提供互补能力，但不应让主角的低 HP 失去意义或成为自动战斗的旁观者。

## 6. 战斗规则准则与伤害模型

本节定义后续规则设计应遵循的骨架，具体面板数值须经小型战斗样例校验。

### 6.1 角色与敌人属性

建议将属性区分为三类，避免堆出大量彼此重复的数值：

1. **生存属性**：HP、Shield（外部护甲缓冲）、必要时的状态抗性。
2. **攻击属性**：武器/技能基础威力、攻击类型、命中或命中规则、护甲/抗性穿透（只有玩法需要时才加入）。
3. **行动资源**：AP、技能资源（如注射者的 MP，若最终保留）、冷却/次数限制。

敌人可以有独特机制、攻击意图、抗性和弱点，但不应只是把玩家属性整体乘高。优先用不同的行动模式迫使玩家换装备、改变目标优先级或消耗特定资源。

### 6.2 普通攻击与攻击类型

- **普通攻击**是基础、可重复使用的动作，应有稳定成本和可靠表现；它不应在所有局面都胜过消耗型技能。
- **物理攻击**依赖武器和物理防御/护甲关系，可承担稳定输出、破甲、打断等不同定位。
- **魔法攻击**依赖技能条件和资源，不应只是物理伤害的高数值替代品；可以通过属性弱点、范围、状态效果或特殊目标规则提供差异。
- 普通攻击可属于物理类型，但规则上要分清“动作类别（普通攻击/技能）”与“伤害类型（物理/魔法/其他）”，方便扩展。

### 6.3 伤害结算顺序（建议作为统一基准）

对一次命中，按固定顺序处理并在战斗日志中可解释：

1. 验证行动是否合法、资源足够、目标有效。
2. 结算命中/闪避或自动命中规则（原型可先选择一种简单明确的方案）。
3. 计算基础威力与熟练度/技能系数。
4. 应用攻击方增益、目标弱点/抗性及防御减值。
5. 应用随机波动（若采用）；随机幅度必须足够小，不能掩盖玩家决策。
6. 得出非负的最终伤害；明确最小伤害规则，避免高防御导致公式出现负数。
7. Shield 吸收伤害；溢出才扣除 HP，并处理破甲/破裂事件。
8. 触发命中后效果、状态效果、反击和战斗结束检查。

结算顺序一旦确定，物理和魔法应尽量共用通用管线，只在防御类型、资源和效果上有差异；避免每种技能各自发明一套隐性顺序。

### 6.4 Buff、Debuff 与特殊效果

每个效果定义：目标、数值/规则变化、持续时间或次数、叠加规则、刷新规则、移除条件、是否可抵抗及战斗日志描述。

- 同一效果默认不无限叠加；应在“刷新时长、取较强值、有限层数”中明确选一种。
- 增伤/减伤 Buff 应受上限控制，避免乘算叠加形成无界倍率。
- 控制效果（眩晕、缴械等）需要持续时间短、可预告或可解除，并给敌人/玩家合理反制机会。
- 状态效果应提供功能差异，而不只是持续扣血/增伤的不同名字。
- 若技能同时带伤害与控制，成本和强度需共同评估，不能只看直接伤害数字。

### 6.5 生存压力与公平性

- 主角低 HP 意味着受击危险，因此敌人高威胁行动应可读、可响应；致死结果应能追溯到行动选择或资源不足。
- Shield 的破裂和溢出伤害应明确显示。装备强度不能让护甲成为永久无损的第二条无限生命条。
- 同一敌人的难度优先来自机制组合与行动压力，而非大量 HP/攻击力膨胀。
- 失败后应能看出是构筑、判断、行动顺序还是资源管理出了问题；尽量避免纯随机的一击即死。

### 6.6 平衡检查准则

设计新装备/技能/敌人时，至少检查：

- 相同遭遇中，不同可行构筑是否都有清楚的获胜路线。
- 新选项是否让旧选项失去用途（严格支配）；若是，是否确有替换旧内容的目的。
- 每回合伤害、敌人预计存活回合、主角可承受命中数、护甲破裂风险和资源消耗是否符合目标节奏。
- 控制/恢复/防御是否会形成无限循环或无风险拖延。
- 最强组合是否依赖稀有掉落、单一技能或重复刷取；若是，需增加代价、限制或替代路线。
- 随机掉落和概率判定是否可复现，便于 Headless 平衡比较。

### 待决定

- HP、AP、回合顺序、敌我行动结构、状态异常及战斗胜败条件。
- Shield 是一次性护甲值、可修理耐久，还是每场战斗恢复的缓冲层；不同防具的承伤与破裂反馈。
- 武器熟练如何有限成长（若保留）、是否存在上限、AP 减耗规则和重型装备门槛；熟练不能成为重复刷怪的无限收益来源。
- 是否引入肌肉量，以及它与力量、负重或装备的关系。
- 物理伤害公式在最小伤害、暴击、随机波动、护甲穿透和伤害减免下的最终顺序。
- 魔法伤害公式的最终数值范围、阵营倍率意图及其与防御/属性耐性的结算顺序。
- 敌人如何攻击、是否有意图预告、Boss 是否有阶段，以及逃跑/失败如何处理。

## 7. 队友、招募与关系

### 已确定

- 战斗中可消耗 AP 邀请敌人加入队伍。成功率由基础概率、双方阵营差距和敌人剩余 HP 比例共同影响。
- 超出敌人的“交友圈容忍阈值”时，招募直接失败并激怒对方。
- 怪物队友阵营固定，不能通过注射改变。
- 人类队友拥有独立固定阵营；只接受与自己坐标相近的样本，部分极端纯人类队友拒绝一切注射。违背其边界可能导致排异、叛变或反目。

### 设计原则

- 招募对象的动机、容忍阈值和入队条件应能从台词、战斗行为或情报中逐步读出。
- 队友的“拒绝注射”是角色设定与关系边界，不应被当成普通好感度惩罚。
- 招募失败后果应明确且可预期；失败不应让同一敌人无限重复接受尝试而没有代价。

### 待决定

- 队伍人数上限、替补/编队规则、队友是否独立行动及控制方式。
- 招募是永久加入、临时协助、战后加入还是概率判定后二择一。
- `AlignmentDiff` 具体是怎样计算的；坐标是否归一化；公式权重、BaseRate、上下限和阈值如何定义。
- 失败激怒会导致什么具体后果、持续多久；是否有再次交涉机会。
- NPC 态度除阵营外，还受哪些变量影响（信任、任务、资源、过往决定）。
- 人类队友样本接受范围如何判定；排异、叛变和反目分别有哪些触发条件及挽回机会。
- 怪物队友强化所需资源、强化上限及其战斗/叙事表现。

## 8. 整备阶段与设施

### 已确定

整备阶段是无跑图的菜单化设施交互。README 提到：

- 医疗所/休息区：恢复整备、触发 NPC 动态对话。
- 黑市/炼金工坊：买卖武器、防具、战术道具和注射样本。
- 情报屋/议事厅：与态度会随阵营坐标动态变化的 NPC 交互。
- 武器库/训练场：管理武器熟练度与队伍配置。

### 待决定

- 整备地点是固定据点、随章节变化，还是在每场战斗之间提供统一菜单。
- 货币/物资来源、商店库存刷新、价格和稀缺资源规则。
- 休息是否推进时间、刷新敌情、改变 NPC 状态或影响任务时限。
- 训练场是否消耗时间/资源；武器熟练能否在战外训练。
- 动态对话如何触发，如何保证重复游玩与自动化测试结果可复现。

## 9. 剧情推进与结局（暂缓细化）

### 已确定

最终 Boss 被击败时依据侵蚀度与双轴坐标判定结局：

| 结局 | 当前条件 |
| --- | --- |
| 天使类 | 侵蚀度 100%，秩序 > 50，正义 > 50 |
| 堕天使类 | 侵蚀度 100%，秩序 > 50，邪恶 < -50 |
| 异神类 | 侵蚀度 100%，混沌 < -50，正义 > 50 |
| 恶魔类 | 侵蚀度 100%，混沌 < -50，邪恶 < -50 |
| 未完全进化 | 0% < 侵蚀度 < 100% |
| 纯人类 | 侵蚀度 0%（全程零注射） |

在本文暂定的坐标符号下，秩序/正义为正向，混沌/邪恶为负向。

### 待决定与规则缺口

- 侵蚀度 100% 但坐标不满足四类条件时的结局是什么？是否存在第五种“完全异变但不归属”结局？
- `0% < 侵蚀度 < 100%` 是否不看阵营坐标，统一进入未完全进化结局？
- 阈值条件是否包含等于 50/-50 的边界；小于 100% 但因四舍五入显示 100% 如何判定？
- 若同一角色同时满足多个条件，判定优先级是什么？目前四个象限看似互斥，但应以正式坐标定义验证。
- “全程零注射”和“当前侵蚀度为零”是否严格等价；如果侵蚀可恢复，需要单独记录注射历史。
- 结局判定是否只看主角，队友状态、重要剧情选择或 Boss 处理方式是否参与？
- 章节主线、关键任务、信息揭示节奏、Boss 身份和结局演出均未定义。

## 10. 公式与实现前待统一项

当前候选公式见[角色属性与战斗规则](character-combat.md)，均不视为已完成平衡的最终规则。

### 物理伤害

物理伤害按基础物攻、所选武器攻击力、武器熟练度加成和目标防御计算。熟练度不是角色等级。公式与说明见[角色属性与战斗规则](character-combat.md)。

### 魔法伤害

魔法伤害将基础魔攻、法术威力、阵营倍率、目标防御和对应属性耐性纳入计算。公式见[角色属性与战斗规则](character-combat.md)。坐标绝对值表达偏离中立程度；是否应影响伤害及其幅度待验证。

### 招募概率

`SuccessProbability = BaseRate + w1 × (1 - AlignmentDiff) + w2 × (1 - CurrentHP / MaxHP)`

待明确各项量纲、`AlignmentDiff` 的范围/归一化方式、概率截断区间、敌人容忍阈值的计算方式及概率检定随机种子策略。对 Headless API 和 RL 可复现性而言，随机源应可由调用方控制或记录。

### 护甲结算

- Shield 吸收伤害；不足时本体承受溢出伤害。

待明确 Shield 是否在吸收时扣减、等于伤害时是否恰好耗尽、护甲破裂后是否仍可防御，以及多段伤害如何逐段结算。

## 11. 建议的设计决策顺序

在开始实现完整战斗系统前，建议按以下顺序完成设计；每项可以先有简短答案，不要求一次写成完整小说：

1. **战斗目标节奏**：一场普通战斗希望几回合结束；主角可承受几次命中；行动资源如何形成取舍。
2. **战斗状态与结算**：HP、Shield、AP、命中规则、伤害顺序、状态效果与胜败处理。
3. **构筑边界**：装备槽/携带上限、消耗品补给、技能配置数量、样本库存与注射代价。
4. **样本掉落和异变规则**：敌人掉落、样本用途、技能获取、侵蚀和构筑影响。
5. **阵营行为映射**：确认两轴的行为定义、坐标变化和结局/技能门槛使用方式。
6. **敌人设计模板**：用攻击意图、弱点、抗性、护甲和机制差异塑造敌人，而非只调高面板。
7. **小型可玩验证范围**：用一场普通遭遇、一名高压敌人、一种样本掉落和数套可行配置检验节奏及平衡。
8. **故事与角色**：战斗语言和规则稳定后，再把故事、人物动机和章节内容接入。
